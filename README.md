# AlRmh

Customer app for AlRmh tailored thobes (Doha): design a thobe, book a measurement, pay, track the order, and earn and redeem points. English and Arabic (right-to-left).

| Folder | What it is |
| --- | --- |
| `apps/mobile` | Expo (React Native) app: iOS, Android and the web PWA from one codebase |
| `apps/api` | NestJS API on PostgreSQL: auth, catalogue, family and measurements, bookings, basket, orders, payments, points, staff and audit log |
| `apps/admin` | Admin web app for staff (React + Vite): orders board, appointments, customers and measurements, catalogue, branches, fees, rewards, staff |
| `render.yaml` | Render blueprint for the API, its database and the admin site |
| `.github/workflows/pwa.yml` | Builds the PWA and publishes it to GitHub Pages on every push to `main` |

Designs: [AlRMH in Figma](https://www.figma.com/design/wb9npW3MTKUTTmddJIChnf/AlRMH).

## Preview mode

The preview runs without real SMS or payments:

- **Login:** any Qatar mobile number (8 digits starting 3, 5, 6 or 7) with code `123456`.
- **Demo account:** `5555 1234` has a family, measurements, past orders, an order at Stitching, 1,240 points and a 10% voucher.
- **Payment:** checkout opens a test SADAD page where you can pay, decline or cancel. No money moves.
- **Coupons:** `EID20` (20% off, capped at QAR 100) works; `SUMMER24` shows the expired message.

Order stages, measurements, fees, catalogue and coupons are managed by staff in the admin app.

## First deployment

1. **API and admin on Render.** In Render choose New > Blueprint and select this repo. It creates `alrmh-api`, `alrmh-db` and `alrmh-admin`. Set these when asked:
   - `APP_URL` = the PWA address, e.g. `https://<owner>.github.io/<repo>`
   - `CORS_ORIGINS` = the PWA and admin origins, comma separated, e.g. `https://<owner>.github.io,https://alrmh-admin.onrender.com`
   - `ADMIN_EMAIL` = the email for the first owner login
   - `VITE_API_URL` (on `alrmh-admin`) = the API URL, e.g. `https://alrmh-api.onrender.com`
   
   The API runs migrations, loads the catalogue and demo data, and creates the owner account on first start. The owner password is generated by Render: find `ADMIN_PASSWORD` in the `alrmh-api` service's Environment tab, sign in, then add other staff from the Staff page.
2. **PWA on GitHub Pages.** In the repo go to Settings > Pages and set Source to **GitHub Actions**. Then Settings > Secrets and variables > Actions > Variables and add `API_URL` = the Render URL from step 1. Push to `main` or run the workflow by hand.
3. Open `https://<owner>.github.io/<repo>/` on a phone. On iPhone use Share > Add to Home Screen; on Android use Install app.

Render's free tier sleeps after 15 minutes without traffic, so the first request after a pause takes about a minute. The free database expires 30 days after it is created; upgrade it to a paid plan before then to keep the data.

## Local development

```bash
cd apps/api && npm install && cp .env.example .env && npm run build && node --env-file=.env dist/main.js
cd apps/mobile && npm install && EXPO_PUBLIC_API_URL=http://localhost:4000 npx expo start --web
```

API smoke test (creates a customer, books, pays and delivers an order; signs in as the owner from `ADMIN_EMAIL`/`ADMIN_PASSWORD`): `API=http://localhost:4000 python3 apps/api/scripts/smoke.py 55559999`

## Admin app

Staff sign in with email and password. Every change is recorded in the Activity log with the staff member's name.

| Role | Can |
| --- | --- |
| Owner | Everything, including staff accounts |
| Manager | Everything except staff accounts: cancel orders, adjust points, edit catalogue, fees, branches, rewards and coupons |
| Tailor | Move orders through stages, record measurements, manage appointments |
| Support | Read only: look up customers, orders and appointments |

Local: `cd apps/admin && npm install && VITE_API_URL=http://localhost:4000 npm run dev`. Start the API with `ADMIN_EMAIL` and `ADMIN_PASSWORD` set to create the first owner.
